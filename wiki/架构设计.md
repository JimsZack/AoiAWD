## 核心模块

### 1. HTTP Server

**职责**: 提供 Web API 和静态文件服务

**实现**:
- 基于 `net/http.ServeMux` 路由
- RESTful API 设计
- CORS 支持
- 静态文件服务

**端点**:
- `/api/v1/*` - REST API
- `/websocket` - WebSocket 连接
- `/*` - 静态文件

### 2. TCP Receiver

**职责**: 接收探针数据

**实现**:
- 基于 `net.Listener` 的 TCP 服务器
- JSON 行协议解析
- 多路复用支持
- 心跳检测

**消息处理**:
```
TCP 连接 → JSON 解码 → 消息分发 → 插件处理 → 存储
```

### 3. Plugin Manager

**职责**: 管理插件生命周期

**实现**:
- 全局插件注册表
- 钩子系统 (routine/operation)
- .so 动态加载
- 热重载支持

**钩子类型**:
- `Web/processLog` - Web 日志处理
- `PWN/processLog` - PWN 日志处理
- `FileSystem/processLog` - 文件事件处理
- `Process/processLog` - 进程事件处理

### 4. Storage

**职责**: 数据持久化

**实现**:
- 内存存储 (默认)
- JSON 文件存储
- 容量限制和淘汰机制

**存储集合**:
- `web` - Web 日志
- `pwn` - PWN 日志
- `filesystem` - 文件事件
- `process` - 进程日志
- `alert` - 告警日志

### 5. WebSocket Hub

**职责**: 实时通知前端

**实现**:
- 客户端管理
- 批量推送 (1.5秒)
- 消息类型标记

## 数据流

### Web 流量处理流程

```
TapeWorm → TCP → Receiver → handleWeb()
    ↓
Plugin Manager (Web/processLog)
    ↓
FlagBuster (检测/替换 flag)
    ↓
Storage (保存到 web 集合)
    ↓
WebSocket Hub (通知前端)
```

### PWN 流量处理流程

```
Guardian → TCP → Receiver → processPWNStream()
    ↓
Plugin Manager (PWN/processLog)
    ↓
FlagBuster (检测/替换 flag)
    ↓
Storage (保存到 pwn 集合)
    ↓
WebSocket Hub (通知前端)
```

### 文件事件处理流程

```
RoundWorm → TCP → Receiver → handleNewFile()
    ↓
Plugin Manager (FileSystem/processLog)
    ↓
KingWatcher (赛点文件监控)
ZombieKiller (不死马检测)
    ↓
Storage (保存到 filesystem 集合)
    ↓
WebSocket Hub (通知前端)
```

## 安全设计

### API 认证

```
请求 → Token 验证 → API 处理 → 响应
         ↓
      无效 Token → 401 Unauthorized
```

### 速率限制

```
请求 → IP 提取 → 频率检查 → API 处理
                   ↓
              超频 → 429 Too Many Requests
```

### 路径安全

```
静态文件请求 → 路径清理 → 前缀检查 → 文件服务
                   ↓
              路径遍历 → 403 Forbidden
```

## 性能优化

### 并发模型

- **goroutine**: 轻量级并发
- **channel**: 数据传递
- **sync.Map**: 并发安全映射

### 内存管理

- **容量限制**: 最大 50000 条记录
- **批量淘汰**: 超出时批量删除最旧记录
- **脏标记**: 文件存储延迟写入

### 网络优化

- **TCP Keepalive**: 连接保活
- **批量推送**: WebSocket 1.5秒批量
- **JSON 行协议**: 减少解析开销
